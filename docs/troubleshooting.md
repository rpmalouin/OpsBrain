# Troubleshooting

| Symptom | Cause / fix |
|---|---|
| `collector works but reasoner returns {}` | Qwen3/Ollama shape wrong. Ensure the selected model is a thinking model, `ollama.think: true`, and that `format:json` is NOT set. Warm the model (`curl localhost:11434/api/tags`). See docs/reasoning-llm.md. |
| reasoner stage fails: `HTTP 400 ... does not support thinking` | The model chosen from `ollama.model`/`fallback_model`/`alt_models` is not a thinking model. `think` is sent per model (from `/api/show` capabilities) — a non-thinking model must not receive it. Pick a thinking model or list the non-thinking one under `alt_models`. |
| LLM actions vanished but deterministic ones still ran | `logs/actions_result.json` → `reasoner.fresh: false`: the decision on disk was made for an older collector snapshot (the stage failed), so the LLM half was suppressed instead of replaying it. |
| `actions_result` skips everything | `actions.dry_run` is true (the default — intentional). It will keep doing this until you set it false (docs/remediation.md). |
| `docker.sock` permission denied | Run as `root` or add the user to the `docker` group, then restart the service. |
| GPU metrics empty / no GPU panel | Check whether `nvidia-smi` itself works. `Failed to initialize NVML: Driver/library version mismatch` = userspace NVIDIA packages were upgraded without reloading the kernel module — every host-side GPU read fails, the collector reports `gpu.available: false` + the error, GPU drift detection is blind, and a `gpu_unavailable` notification fires once/day. Containers can still use the GPU meanwhile — verify with `docker logs ollama \| grep offloaded`. Fixed by rebooting the VM (or unloading `nvidia*` with all GPU consumers stopped). The host now also repairs this itself: `/etc/apt/apt.conf.d/99-nvidia-module-reconcile` runs `/usr/local/sbin/nvidia-module-reconcile` after every apt operation and reloads the module when loaded ≠ on-disk — UNLESS a GPU container holds the device, in which case it **defers** and logs the remedy to `/var/log/nvidia-module-reconcile.log`. OpsBrain ingests that log (`collector.json` → `gpu_reconcile`, dashboard GPU Drift strip, `notify_gpu_reconcile` once/day) and shows the exact command: `docker stop <gpu-containers> && /usr/local/sbin/nvidia-module-reconcile --force`. If `nvidia-smi` works but metrics are empty, it's not on `$PATH` for the running user. |
| Dashboard exits immediately / restart counter climbing | `journalctl -u opsbrain-ui -n 50` — a repeating `IndexError`/metric error is a UI bug. The UI is meant to start degraded (`initial snapshot failed, starting degraded`) rather than die when a source is missing. |
| Reasoner stage fails, or its decision is ignored | `logs/reasoner_result.json` shows which `model` answered and whether `think` was used; `HTTP 400 ... does not support thinking` means the selected model is not a thinking model (docs/reasoning-llm.md). `reasoner: {fresh: false}` in `actions_result.json` means the decision on disk is for an older snapshot and the LLM half was suppressed on purpose. |
| Federation nodes show **offline** | The `collector_endpoint`s aren't reachable. Each node must serve a snapshot JSON (e.g. its dashboard `/api/status`, or a raw `collector.json`). Test locally by pointing them at `http://127.0.0.1:9120/api/status`. **Check the PORT first:** the endpoint is the node's dashboard port (`:9120`), and a wrong one does not fail loudly — on dockerVM `:8099` is *caddy-editor* (401/404), which made the Cluster Overview read a permanent "0/2 online, stability 0" with a critical `cluster_health_warning` every cycle. `curl -o /dev/null -w '%{http_code}' http://<node>:9120/api/status` must print 200. A node you cannot serve yet is better commented out than left configured, and note the actions stage reads the PREVIOUS cycle's cluster result, so a fix appears one cycle later. |
| TrueNAS source unavailable | Check `~/.smbcred` exists/readable and the user can authenticate (`auth.login_ex`) on `wss://<host>/api/current`. Degrades gracefully if not. |
| A container you stopped keeps getting restarted | With manual-stop protection on this is a hard block — verify it's recorded in `logs/manual_stops.json`. A *crashing* container (OOM / nonzero exit) is NOT protected; that's by design (docs/manual-stop-protection.md). |
| Dashboard WS not updating | Check `opsbrain-ui` is active; the server watches the log files in `ui/config.yaml` `watch[]`. Ensure the watched logs exist and are being written. |
| `actions_result.json` `cluster.recommendations` empty | Federation `enabled: false` or no cluster output yet. Run `python3 federation/federation_collector.py && python3 federation/federation_reasoner.py` once. |
| Dockhand shows **unreachable** / `dockhand.up: false` | `sources.dockhand.db_path` doesn't exist or is unreadable (OpsBrain opens it read-only; Dockhand holds it under WAL). Verify the file, then run `python3 collector/collector.py` once. Degrades gracefully otherwise. |
| Dockhand shows **drift for every stack** (policy flood) | The matched container record is missing `labels` (restart-policy inference needs `com.docker.compose.*`). Confirm `dockhand.merged[].actual.labels` is populated; the collector's `docker.containers` must carry `labels`. |
| Dockhand flags `Firefox` as orphaned/state-drift | Name matching is case-insensitive, but only if the container name matches a stack/service. Confirm the stack exists in `stack_sources` for `environment_id`; else it's a genuinely unmanaged container. |
| Caddy site won't appear after editing Caddyfile | Bind-mount inode staleness — `docker restart caddy` to re-bind the file (docs/dashboard.md). |

## Quick diagnostics

```bash
journalctl -u opsbrain -f          # pipeline log
journalctl -u opsbrain-ui -f       # dashboard log
python3 scheduler/scheduler.py --once   # force a cycle (dry)
python3 scheduler/scheduler.py --report # force today's report
python3 -m pytest -q               # run the test suite
```
